**External defect screening — Step 9B**

This is a source-based shortlist, not a reproduced benchmark or new vulnerability discovery. The screening covers all four entries explicitly assigned the authentication/authorization/session category and nine storage/access entries in the [Defects4REST executable list at commit 265db116](https://github.com/ANSWER-OSU/Defects4REST/blob/265db1165e54b01a0698af0fd28d345169a5449f/bug_replication/README.md). That release lists 110 executable cases across twelve projects. The remaining categories were not exhaustively screened; taxonomy membership is neither an inclusion rule nor proof of authorization failure. **Oracle discrepancies found during screening**

The Dolibarr replication instructions expect HTTP 403, while the inspected fixing commit throws an authorization exception with HTTP 401. Both must be distinguished from protected currency disclosure; copying the dataset's expected status as the sole oracle would mislabel the fix. The Mastodon reproduction describes an empty HTTP 200 response after reading a deleted subscription. The [pinned fixed controller](https://github.com/mastodon/mastodon/blob/61b7a04528e875e61361bb22ed3b45fbee38f3fd/app/controllers/api/v1/push/subscriptions_controller.rb) calls its not-found path when no subscription exists, and the [official API reference](https://docs.joinmastodon.org/methods/push/#get) documents 404 for that condition. Verify behavior on the exact tested revision instead of adopting the reproduction's status expectation.

**Selection before any external effectiveness run**

Retain Dolibarr as a static diagnostic and Mastodon as a possible separate concurrency/effect extension. Neither is integrated or counted as a detected defect in this checkpoint. Reviewed bug descriptions cannot later be presented as blind held-out cases. A future study must preregister revision pairs, inclusion/exclusion criteria, independent policy review, test inputs, reset semantics, protected observations, timing/queue assumptions, budgets and tool configurations before executing comparative measurements. Preserve failed reproduction attempts and unsupported cases in the final coverage report.

The structured [screening manifest](results/step9b-screening.json) records revision provenance and current decisions. This thirteen-entry screen does not clear the held-out-family or independent-review gates.
